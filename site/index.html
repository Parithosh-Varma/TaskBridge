Why it exists

Planners plan.
Runners run.

Claude is a great planner but can't touch your machine. OpenCode runs code locally but lives outside Claude's context. The bridge connects them with a queue that survives restarts, supports retries and priorities, and lets either side ask questions mid-task.

Delegate, don't babysit

One submit_task call fans out to a headless agent. Poll once with wait_for instead of looping.

Answers, not just logs

Every completion carries a structured summary, files touched, tests run, open questions — plus a git-aware diff.

Stuck? It asks back

The worker can pause a task with a question. You answer, it resumes with your answer in context.

Per-task isolation

Each task can run on its own branch in a git worktree, auto-committed on success and cleaned up after.

Honest permissions

readonly reverts writes and reports what was reverted. Network/shell limits are prompt-level and labeled as such — never oversold.

Taste

Three calls. Done.

claude → bridge
# 1. dispatch
submit_task(title="Add retry tests", working_dir="/path/to/repo",
  instructions="Cover task_store retries. pytest must pass.")  →  id: t-3f2a

# 2. wait (no poll loop)
wait_for(task_ids=["t-3f2a"], timeout_sec=120)

# 3. read the structured result
get_task_result(task_id="t-3f2a")  →  { summary, files_touched, tests_run, diff }
