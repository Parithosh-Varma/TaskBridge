Why it exists

Planners plan.
Runners run.

Claude is a great planner that can't touch your machine. OpenCode runs code locally but lives outside Claude's context. The bridge connects them with a queue that survives restarts — retries, priorities, dependencies, and questions in both directions included.

01

Delegate, don't babysit

One submit_task call fans out to a headless agent — submit_batch takes up to 20. Poll once with wait_for instead of looping.

02

Answers, not just logs

Every completion carries a structured summary, files touched, tests run, and open questions — plus a git-aware diff.

03

Stuck? It asks back

The worker can pause a task with a question. You answer via answer_task, and the run resumes with your answer in context.

How it runs

Dispatch. Pickup. Collect.

No polling loop, no server to babysit. The handoff is a SQLite file, and everything else is one command away.

01 · DISPATCH

Ask once.

A single submit_task lands in the queue — from Claude Desktop over stdio or any MCP client over HTTP. Priorities, dependencies and retries ride along.

submit_task(title, working_dir, instructions)
02 · PICKUP

The worker claims it.

Within about a minute a headless worker spins a per-task git worktree, runs opencode run, and streams output to task_logs/<id>.log.

opencode run · worktree br/t-3f2a
03 · COLLECT

Read the result.

wait_for blocks until it finishes; get_task_result returns the structured summary and the diff. No babysitting.

wait_for → get_task_result

Prefer to watch? A live dispatch board — tally counts, per-task logs, reverse jobs — is served at GET / on the same host.

Per-task isolation

Each task can run on its own branch in a git worktree, auto-committed on success and cleaned up after.

Honest permissions

readonly reverts writes and reports what was reverted. Network/shell limits are prompt-level and labeled as such — never oversold.

Taste

Three calls. Done.

claude → bridge
# 1. dispatch
submit_task(title="Add retry tests", working_dir="/path/to/repo",
  instructions="Cover task_store retries. pytest must pass.")  →  id: t-3f2a

# 2. wait (no poll loop)
wait_for(task_ids=["t-3f2a"], timeout_sec=120)

# 3. read the structured result
get_task_result(task_id="t-3f2a")  →  { summary, files_touched, tests_run, diff }

Trust

Enforced, labeled,
or not claimed at all.

If a limit is real, it's mechanically enforced. If it's prompt-level, it's labeled as exactly that. And if a number doesn't exist, it isn't printed.

WhatStatusDetail
readonly permissionenforcedWrites are reverted after the run, and every reverted file is reported back.
git worktree isolationenforcedPer-task branch, auto-committed on success, cleaned up unless you ask to keep it.
durable queueenforcedSQLite survives restarts; tasks stuck in running are reaped and requeued after 15 minutes.
auth on public URLsenforcedBearer token on /mcp and /api; only /health stays open.
no-network · no-shelllabeledPrompt-level restrictions, documented as such — not an OS sandbox.
token countsnot reportedThe opencode CLI doesn't expose them. Usage reports model, latency, attempts, sandbox — never faked numbers.
